## Befehle
- `npm test` (node --test), `npx tsc --noEmit -p .`, `npm run check` (alles zusammen) – vor jedem Push grün.
- Beispiel-Spaces: `examples/<name>/index.html`, installieren mit `npm run install:examples` (siehe Skill `space-change`).
- Connector-Bundles: `npm run build:connectors` (alle) oder `node scripts/build-control-tower-mcpb.mjs <id>`. Die älteren Connectoren `gmail`, `databricks`, `jira`, `slack`, `notion` haben eigene Bundle-Flags (`--gmail` usw.).
- Cognee: `npm run cognee:corpus`, danach `.venv-cognee/bin/python scripts/cognee-seed.py [--reset]` (nicht `npm run cognee:seed`, das nimmt das System-Python).

## Policy-Manifest (Stand 05.11.2026, Branch `feat/policy-manifest`)
- **Stufe 1 einer Governance-Schicht unter der Werkbank:** was ein Agent oder Workflow darf, als Daten, bei jeder Revision mitgespeichert (Datei `policy.json` im Work Item). **Es erzwingt nichts**; es macht die deklarierten Rechte lesbar und vergleichbar. Gedacht als Eingabe für eine spätere Ausführungsschicht (z. B. Sandbox mit Netz- und Dateiregeln, etwa NVIDIA OpenShell, wie SAP es in die Joule-Studio-Runtime einbettet); diese Stufe ist ausdrücklich **nicht** gebaut.

Modi geordnet: read-only < draft < act-after-approval < autonomous. Keine zusätzliche Eingabe, kein Auseinanderlaufen von Projekt und Manifest. **Was die Formulare nicht fragen, bleibt `null` = "nicht deklariert"** (`tools` = Werkzeug-Liste, `egressHosts` = Netzziele) und wird von `policyGaps` als Lücke benannt, nie als Grenze erfunden.
- `src/work-sync.ts`: `agentUnit`/`developUnit` hängen `policy.json` an die Dateien und eine kleine Zusammenfassung an den `intent` (`intent.policy`). Der Hash deckt weiter nur `project.json`: **bestehende Einträge bekommen das Manifest erst bei ihrer nächsten Änderung** (keine Revisionsflut). Restore (`rollbackArgs`) kopiert die Datei mit.
- Registry (`RegistryView.tsx`, Panel `PolicyPanel`, Stile `.rg-pol-*`): je gewählter Revision die deklarierten Rechte, die Lücken, und was gegenüber der Vorrevision **weiter** (wider), **enger** (narrower) oder neutral wurde (`diffPolicy`, `revisionPolicy`); "This revision gives the item more room" bei jeder Erweiterung. Eine Revision ohne Manifest (vor dieser Änderung gespeichert) zeigt den Grund und keine Vergleichsliste, sie gilt weder als "nichts erlaubt" noch als "alles erlaubt". Keine neue Migration, keine neue Tabelle.

Systeme eines Agenten stehen mit ihrer Quellen-Id, nicht mit einer Zuordnung zu Connector und Werkzeug.
