How categorization works

Each workflow is sorted by its n8n tags. The first category whose tags match wins, so the order in the table is the priority.

To pin a workflow, give it the n8n tag cat:Finance & Procurement (any category name). Pinned workflows ignore the rules.

The rules live in examples/automation-dashboard/categories.json. Time saved is an estimate: successful runs times the minutes per run assumed for the category.

Where the data comes from. The page cannot reach n8n itself, so the numbers are embedded into it. Without setup you see fictional sample data.

Load your n8n Cloud data. In n8n create an API key (Settings, n8n API) and run in the project folder:

N8N_URL=https://your-instance.app.n8n.cloud N8N_API_KEY=… npm run sync:automation -- --live

Then reopen this Space. The key only lives in that command; it is not stored anywhere.

What is read. Workflow names, tags, active state, node types (to show trigger, connected apps and model nodes) and the workflow dates, plus status, mode and duration of the last 14 days of executions. No execution payloads: error messages, tokens and data of a run are never read.

Tag conventions. cat:<category> pins the category, project:<name> and owner:<name> say who built what for which project, reviewed:<YYYY-MM-DD> records the last review. They drive the Builders and Governance tabs.

People. Owner names are only embedded when you add --people to the command. Without it the Builders tab shows projects and counts only. This page has no sign-in: whoever can open it can use the switch, so do not load names for a wide audience, and check works-council and data-protection rules before you do.

Assumptions. Success target, hourly rate, plan limit and model prices live in examples/automation-dashboard/settings.json. Time saved and model cost are estimates from these assumptions, not measurements.
